# AGENTS.md

## Cursor Cloud specific instructions

### Product
This repo's primary product is **Aether** (repo root), a Next.js 15 (App Router) AI chat app. Default access is **Aether Cloud** (hosted models via server-side keys); users can also **Bring Your Own Key** (BYOK keys stay in the browser). Optional Auth.js sign-in plus `DATABASE_URL` (Neon) or `AETHER_PGLITE=1` enables cloud conversations, curated memory, projects, persisted artifacts, and harness run rows. Without a DB, chat history and local memory use `localStorage` (`aether:` prefix). The only required local process is the Next.js dev server. The `Match website layout/` subfolder is an unrelated standalone Figma/Vite export — ignore it unless specifically asked.

### Standard commands (root)
Defined in `package.json`: `npm run dev` (port 3000), `npm run build`, `npm run start`, `npm run lint`. Node >=20 required. Dependencies are installed by the startup update script (`npm install`).

### Non-obvious notes
- **Hosted + BYOK.** Default `accessMode` is `hosted`. Client sends `x-access-mode: hosted` (no user key). Server routes via `src/lib/hosted/*` using `OPENROUTER_API_KEY` + optional `AETHER_HOSTED_BUZZ_*` (Claude + ChatGPT; legacy `AETHER_HOSTED_CLAUDE_*` aliases). Status/catalog: `GET /api/hosted/status` returns a live ranked OpenRouter catalog (ChatGPT → Claude → More; default OpenAI). Does not expose vendor names or keys. BYOK still sends `x-api-key` / `x-provider` / `x-base-url` from Settings. Never store user API keys in the server DB.
- **Optional cloud DB.** When `DATABASE_URL` or `AETHER_PGLITE=1` is set and the user is signed in, conversations sync to Postgres and APIs under `/api/memory`, `/api/projects`, `/api/artifacts`, plus harness tables (`agent_runs`) become available. Unsigned or no-DB users keep using `localStorage`.
- **Agent harness (UX only on the Hermes path).** Composer send still classifies via `POST /api/harness/classify` (clarify cards + depth budgets 2/8/16). Chat body may include `harness` (`intent`, `depth`, `runId`, `clarifications`, `planSteps`), `memoryContext`, `projectId`, `conversationId`. Those become **system-prompt notes** on the Hermes path. The in-process `prepareStep` / progressive unlock loop in `src/lib/harness/loop-efficiency.ts` is **legacy** — used only for BYOK and hosted fallback when Hermes env is unset. New agent-loop work goes in `src/lib/hermes/`.
- **Remote Hermes (hosted live path).** When `HERMES_BASE_URL` + `HERMES_API_KEY` are set, hosted `/api/chat` is a thin orchestrator: Auth.js (optional), assemble context, `POST {HERMES_BASE_URL}/v1/chat/completions` with `Authorization: Bearer HERMES_API_KEY`, `X-Hermes-Session-Id` (conversation), `X-Hermes-Session-Key` (`aether:user:{id}` or `aether:anon:{conversationId}`), picker `model` + `provider` (hosted ChatGPT/Claude → `custom:buzz`, other hosted models → `openrouter`, unless `HERMES_PROVIDER` is set). Bridges OpenAI SSE + `hermes.tool.progress` into the AI SDK UIMessage stream (`providerExecuted: true`). Stop aborts the fetch and, if a Hermes `run_id` appeared, `POST /v1/runs/{id}/stop`. Users never install Hermes; the browser never calls it. BYOK stays on the isolated local `streamText` path — user keys are not sent to Hermes. If Hermes env is missing, hosted falls back to OpenRouter/BUZZ when those keys exist; if neither is configured, `/api/chat` and `/api/hosted/status` fail clearly (`available: false` / 503) instead of hanging on “Chat isn’t ready”. See `docs/superpowers/specs/2026-08-12-hermes-remote-backend-design.md` and `deploy/hermes/`.
- **Aether tool seam (Phase 3).** Hermes owns web, fetch, code exec, sandbox files. Aether owns memory DB, Drive, GitHub, persisted artifacts, and confirm cards — those execute on Vercel (`src/lib/hermes/aether-tools.ts`) via the hosted same-turn loop and `POST /api/hermes/aether-tools`. The browser never talks to Hermes; Hermes never receives Drive/GitHub tokens. Official chat-completions does not accept per-request custom tools, so Aether (a) registers a host plugin that callbacks into Vercel, and (b) executes declared Aether tools from OpenAI `tool_calls` / `[[aether_tool]]` fences and feeds results back in the same turn. Do not wire Aether tools as in-process `streamText` tools on the Hermes path. **Ask** (default) confirms mutations; **Auto** runs routine/non-destructive Aether tools without a tap. Destructive / spend / third-party submit / delete / someone-else’s Drive or GitHub always confirm. Preference: signed-in+DB via `/api/preferences`; guests use `aether:settings:v1`. Confirm cards persist in `pending_confirmations` when cloud DB is on. If a connector is not connected, the seam says so instead of pretending the tool works.
- **Auth (email magic link) works without OAuth.** Email sign-in uses a signed JWT + Credentials provider. Locally, `/api/auth/email` returns a `devLink` when `AUTH_RESEND_KEY` is unset — open that link to finish sign-in. `AUTH_SECRET` is optional locally (shared fallback in `src/lib/auth-secret.ts`); set a real secret for production. OAuth (Google/GitHub/Apple) only appears when the matching env vars are set. Provider flags for the sign-in UI live at `/api/auth/configured` (do not use `/api/auth/providers` — that path belongs to Auth.js).
- **Drive / GitHub connect.** After OAuth (or when login is required first), the app returns to `/?connect=drive` or `/?connect=github`, which opens Settings — there is no `/settings` route. Drive uses `aether.drive` cookie; GitHub connector uses `aether.github` (separate from Auth.js sign-in). Add `/api/github/callback` on the GitHub OAuth App alongside `/api/auth/callback/github`.
- **`fetch_url` is SSRF-hardened** in `src/lib/connectors/url-safety.ts` (blocks private/link-local/metadata hosts, validates DNS, caps redirects). Do not weaken this without review.
- **Testing chat end-to-end.** For hosted: set `OPENROUTER_API_KEY` (and optionally Claude/GPT gateway keys) in `.env.local`. For BYOK without a real provider: Settings → Bring your own key → Custom provider; point Base URL at a local mock OpenAI-compatible server (`POST /chat/completions` with OpenAI SSE) and set any API key + custom model id. Keep mock servers outside the repo (e.g. `/tmp`).
- **Settings dialog auto-opens** when the user cannot chat yet (hosted unavailable and no BYOK key). Keys/history persist in browser `localStorage` under the `aether:` prefix. Memory inspector lives in Settings; projects + saved artifacts appear in the sidebar when cloud is on.
- Lint may emit a `react-hooks/exhaustive-deps` warning in `src/components/model-picker.tsx` (0 errors).
