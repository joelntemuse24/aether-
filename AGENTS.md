# AGENTS.md

## Cursor Cloud specific instructions

### Product
This repo's primary product is **Aether** (repo root), a Next.js 15 (App Router) AI chat app. Default access is **Aether Cloud** (hosted models via server-side keys); users can also **Bring Your Own Key** (BYOK keys stay in the browser). The cream UI, Auth.js, Settings, Neon, and Drive/GitHub connectors stay on this Next.js app. When `TRIGGER_SECRET_KEY` and `TRIGGER_PROJECT_ID` are set, every chat turn (hosted and BYOK) runs as a durable `chat.agent` (`src/trigger/chat.ts`) — Trigger is not a Next host. Optional Auth.js sign-in plus `DATABASE_URL` (Neon) or `AETHER_PGLITE=1` enables cloud conversations, curated memory, projects, persisted artifacts, and harness run rows. Without a DB, chat history and local memory use `localStorage` (`aether:` prefix). The only required local process is the Next.js dev server. The `Match website layout/` subfolder is an unrelated standalone Figma/Vite export — ignore it unless specifically asked.

### Standard commands (root)
Defined in `package.json`: `npm run dev` (port 3000), `npm run build`, `npm run start`, `npm run lint`. Node >=20 required. Dependencies are installed by the startup update script (`npm install`).

### Non-obvious notes
- **Hosted + BYOK.** Default `accessMode` is `hosted`. Hosted Cloud uses server keys (`OPENROUTER_API_KEY` + optional `AETHER_HOSTED_BUZZ_*`; legacy `AETHER_HOSTED_CLAUDE_*` aliases) on Vercel and on the durable-agent worker — never send those to the browser. Status/catalog: `GET /api/hosted/status` returns a live ranked catalog plus `chatTransport: "durable" | "request"` (internal; not shown in UI). Does not expose vendor names or keys. BYOK keys stay in browser `localStorage`. On the request fallback they are sent as `x-api-key` / `x-provider` / `x-base-url` to `/api/chat`. On the durable path they are passed only as ephemeral per-turn `clientData` (never Trigger env, Neon, logs, or session dumps). Never store user API keys in the server DB.
- **Optional cloud DB.** When `DATABASE_URL` or `AETHER_PGLITE=1` is set and the user is signed in, conversations sync to Postgres and APIs under `/api/memory`, `/api/projects`, `/api/artifacts`, plus harness tables (`agent_runs`) become available. Unsigned or no-DB users keep using `localStorage`.
- **Durable chat.agent (hosted live path).** When `TRIGGER_SECRET_KEY` and `TRIGGER_PROJECT_ID` are set, `useChat` uses `useTriggerChatTransport`. The **first turn** POSTs `POST /api/chat/head-start` (`chat.headStart`): step 1 `streamText` runs on this warm Next process (hosted Buzz-first) while the agent boots. Tool execution and later turns stay on the worker. Subsequent turns use the session PAT from response headers (mint-token only to refresh; start-session is not on the first-send path). Composer send must not wait on `/c/<id>` navigation or conversation create. Idle sessions suspend and cost nothing. Head-start `maxDuration` is 60 (not the request-path 300 loop). Do not invent a project ref; operators copy `TRIGGER_PROJECT_ID` from their dashboard. `npx trigger.dev@latest dev` / deploy is separate from `npm run dev`. If Trigger env is missing, the client keeps `POST /api/chat` (live site unchanged).
- **Agent harness.** First composer send does **not** await `POST /api/harness/classify` — Head Start must fire on Send. First turn uses sync heuristic extras (and does not hold for clarify cards). Later turns may still classify for clarify cards + depth budgets 2/8/16. Chat extras (`harness`, `memoryContext`, `projectId`, `conversationId`) become system-prompt notes. The in-process `prepareStep` / progressive unlock loop in `src/lib/harness/loop-efficiency.ts` runs inside `runLegacyLocalChat` on both the durable agent and the `/api/chat` fallback.
- **Remote Hermes (unused unless opted in on the `/api/chat` fallback).** Railway/Hermes files stay in the repo but are not the live path. Hermes is off unless `HERMES_ENABLED=1` plus URL + key, and only applies when the client still posts `/api/chat`. See `docs/superpowers/specs/2026-08-12-hermes-remote-backend-design.md` and `deploy/hermes/`.
- **Aether tool seam.** Durable-agent tools owned by Aether (memory, artifacts, Drive/GitHub reads, confirm cards, Ask/Auto) execute on this Next.js app via `POST /api/hermes/aether-tools` with a signed user/conversation context JWT. The worker never receives Drive/GitHub cookies. Confirm cards stay on `/api/harness/confirm` and existing UIMessage parts. **Ask** (default) confirms mutations; **Auto** runs routine/non-destructive Aether tools without a tap. Destructive / spend / third-party submit / delete / someone-else’s Drive or GitHub always confirm. Preference: signed-in+DB via `/api/preferences`; guests use `aether:settings:v1`. Confirm cards persist in `pending_confirmations` when cloud DB is on. If a connector is not connected, the seam says so instead of pretending the tool works.
- **Auth (email magic link) works without OAuth.** Email sign-in uses a signed JWT + Credentials provider. Locally, `/api/auth/email` returns a `devLink` when `AUTH_RESEND_KEY` is unset — open that link to finish sign-in. `AUTH_SECRET` is optional locally (shared fallback in `src/lib/auth-secret.ts`); set a real secret for production. OAuth (Google/GitHub/Apple) only appears when the matching env vars are set. Provider flags for the sign-in UI live at `/api/auth/configured` (do not use `/api/auth/providers` — that path belongs to Auth.js).
- **Drive / GitHub connect.** After OAuth (or when login is required first), the app returns to `/?connect=drive` or `/?connect=github`, which opens Settings — there is no `/settings` route. Drive uses `aether.drive` cookie; GitHub connector uses `aether.github` (separate from Auth.js sign-in). Add `/api/github/callback` on the GitHub OAuth App alongside `/api/auth/callback/github`.
- **`fetch_url` is SSRF-hardened** in `src/lib/connectors/url-safety.ts` (blocks private/link-local/metadata hosts, validates DNS, caps redirects). Do not weaken this without review.
- **Testing chat end-to-end.** For hosted: set `OPENROUTER_API_KEY` (and optionally Claude/GPT gateway keys) in `.env.local`. For BYOK without a real provider: Settings → Bring your own key → Custom provider; point Base URL at a local mock OpenAI-compatible server (`POST /chat/completions` with OpenAI SSE) and set any API key + custom model id. Keep mock servers outside the repo (e.g. `/tmp`).
- **Settings dialog auto-opens** when the user cannot chat yet (hosted unavailable and no BYOK key). Keys/history persist in browser `localStorage` under the `aether:` prefix. Memory inspector lives in Settings; projects + saved artifacts appear in the sidebar when cloud is on.
- Lint may emit a `react-hooks/exhaustive-deps` warning in `src/components/model-picker.tsx` (0 errors).
